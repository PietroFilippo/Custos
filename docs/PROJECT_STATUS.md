# Project status — 5 October 2026

## Current development milestone: 0.5.0

0.5.0 renames the add-on from TabCloser to **Custos** (Latin “guardian”, after *custodia oculorum*, custody of the eyes) ahead of the first public release, and builds on the unreleased 0.4.1 with a redesigned interface, a blur-first presentation for hidden X media, profile protection on X, and fixes for coverage gaps. The add-on gets its permanent public ID `custos@pietrofilippo` (previously `tabcloser@personal.local`); a new ID is a separate Firefox add-on, so the existing development install must be set up again. Permissions are unchanged and new settings default off. A signed release has not been published.

Completed for 0.5.0 (5 October):

- **Blur by default.** Confirmed-sensitive X media stays in place, blurred and darkened, with a corner notice and “Why hidden?”. The blur radius scales with the media cell (fixed-radius fallback first, so an engine that rejected the scaled value would still blur). Clicking blurred media opens “Why hidden?”. **Cover hidden media with sacred art** is an opt-in presentation switch that stays editable under every lock and redraws covers without reclassifying. Upgraded installs move to the blur until it is switched on.
- **Redesign** following the mockups (kept outside Git): settings with at-a-glance status cards, a sticky section menu with lock badges, single column, inline helper text instead of hover tooltips, an Off / X labels / Labels + classifier level selector, and one **Lock…** popover (1 h, 1 day, 1 week, 30 days, until a date) for timers, adult sites, the X level, and the reveal allowance. Locked sections show the exact end and time left. The popup has a header summary, per-area lock chips, and readable site cards. The block page explains the block, shows when early unblock is locked, and offers **Close this tab**; there is still no unblock or “go back” button during a cooldown. “Why hidden?” is sectioned into the reason and the metered reveal.
- **Profile protection on X** (opt-in): account flags come from X’s own account data (`possibly_sensitive` or a sensitive profile interstitial) plus optional explicit name/bio markers. The classifier never flags accounts, and flags live only in page memory; nothing is stored, because a persisted author list previously censored a safe post permanently. Picture/banner scope is Off, flagged accounts only, or everyone except accounts you follow (fail-closed until X reports a follow; your own picture never blurs). Name replacement (plain “Hidden account” or a stable virtue alias such as “Temperance ✝”, including mentions, the profile top bar, and the tab title, with the @handle, bio, and website hidden) and reply collapse apply to flagged accounts only. A live Zen test confirmed blurred pictures/banners and aliases on a flagged profile; the handle, top bar, and serif-font gaps it found are fixed. Collapsed replies reveal through the existing per-post allowance. Profile settings stay editable during an X lock (see “Lock scope” below).
- **Coverage gaps:** a private-window warning in settings and the popup when Firefox does not run Custos there; optional SafeSearch enforcement (Google, Bing, DuckDuckGo, Brave Search) sharing the adult-site lock; link-preview images on X are classified and covered as their own cells (the whole card is still never a media root); the unused v1 `x-protection.js` was removed.
- **Rename:** user-visible text, the toolbar title, menus, page titles, log prefixes, the icon file, and package metadata say Custos. Internal identifiers (`TabCloser…` script globals, `tabcloser-` CSS classes and data attributes, storage keys, message types) are unchanged to avoid regressions. The GitHub repository is renamed to `PietroFilippo/Custos` and project links point there; GitHub redirects the old URL.
- **Palette and icon:** every color moved into named tokens (`--accent`, `--ok`, `--warn`, surfaces, and `--tabcloser-*` for controls on X), then switched from charcoal/gold to **Lapis** (ink navy, lapis-blue accent, ivory text; text 16:1, muted and accent above 7:1 on panels). New icon: a shield with a lowered eye (custody of the eyes), readable at 16 px on light and dark toolbars, also used as the small mark on X; PNG exports regenerated. Layout is unchanged.
- **Live-test fixes (quoted posts):** GIF thumbnails (`tweet_video_thumb`, shown alone in timeline quote cards) count as video thumbnails, so the GIF's frames can overrule a noisy thumbnail exactly as in the detail view. Like blocking follows the post's own media, so a censored quoted card no longer blocks liking the post that quotes it (and the CSS `:has()` rule is replaced by a JS-managed attribute). Released media restores text per tweet layer; previously a released quoted card kept its text hidden with no quote. Small cells such as quote thumbnails show a compact mark and a “?” button.
- **Classifier performance:** added the bundled TensorFlow.js WebAssembly backend between WebGL and plain JavaScript, and fixed backend selection, which treated a failed WebGL setup as active because `setBackend` resolves `false` instead of throwing. Measured in a real browser worker: WebGL about 28 ms per image (one-time shader warm-up at startup), WebAssembly about 55 ms (0.4 s first image), plain JavaScript about 1.1 s. Parsing a 40-post X response takes about 5 ms in the background process. Adds about 0.7 MB of `.wasm` files; production dependencies audit clean.
- **Page-side performance:** a live session showed the x.com process at 84% CPU and 2 GB. Profiling a busy X-sized stress page (about 35,000 elements, constant counter updates, posts streaming in and out, account metadata every 2 s) in headless Chrome found two whole-page rescans on every DOM change, the profile refresh and the manual-hides refresh, at about 810 ms of 935 ms of Custos script time per 20 s. Both are now incremental: only elements X added are scanned, Custos's own changes are tracked in memory, full passes happen only on settings, flagged-account, or page changes, and profile work is skipped while no flagged account is known. Profile picture and banner rules target the avatar container and banner link directly (no descendant or `[style*=]` patterns), and the stylesheet is rewritten only when it changes. Covers measure their host once instead of forcing a style recalculation on every redraw; only protected media is size-tracked and removed elements are released (fixing a likely retention of scrolled-away posts); pending covers use a fixed blur; label sets are capped. Result on the stress page: Custos script time 935 ms → about 160 ms, extra style time 193 ms → about 33 ms. This is Chrome on synthetic churn; live Firefox measurements are still needed.
- **Reveals and panel:** the time per post is configurable from 3 to 10 seconds (default 3), enforced by the background ledger and, like the daily allowance, only lowerable under a reveal or X lock. Closing “Why hidden?” returns focus to its button without scrolling the page back to the post.
- **Painting library:** every painting is credited in `assets/sacred-art/CREDITS.json` (title, artist, date, museum, object page), the build refuses uncredited files, and the painting viewer shows the credit with a link to the museum. Files are named for their real subjects. All 361 paintings are public domain or CC0 from four open-access programs (The Met, the Cleveland Museum of Art, the National Gallery of Art, and the Art Institute of Chicago); 61 wide works (Nativities, Adorations, Annunciations, saints’ lives, Madonnas with saints) were added because wide cells such as 16:9 video had only 56 matching paintings, now 117. Additions were reviewed by eye for a calm devotional subject (no Passion, martyrdom, or nude-heavy scenes, no genre scenes or townscapes) and none scores as adult on the classifier. Existing paintings were kept. Packaged copies are re-encoded at JPEG quality 82 (66.8 MB of sources, 34.3 MB packaged), and two posts on the page never show the same painting.
- **Code review (GPT-6.1-Sol, verified and fixed):** enum validation uses own keys only (`"constructor"`/`"__proto__"` previously passed lock checks, and `"__proto__"` disabled the classifier threshold); one lock-deadline validator rejects overflowing durations that became `Infinity` and erased locks; locked timers cannot be reset; locked rules accept only stricter edits; trailing-dot hosts are canonicalized and redirected; text replacement and like blocking lock with X protection; trusted time from server `Date` headers stops system-clock jumps from ending locks, cooldowns, or reveal days early; GraphQL responses that wake the background before settings load are still read; multi-video posts match each video's source by poster; labels-only mode protects late-labeled media-search tiles; quotes return when X redraws only the post text; manual hides and profile aliases follow reused elements and stale aliases are removed; removed pending media is unregistered from the IntersectionObserver; diagnostics summarize free text by length; expired rule locks re-enable their controls without a reload; the painting viewer is a labelled dialog with a Close button; long lock dates show their year. Not changed: safe GIF/video thumbnails shown alone (as in quote cards) are not frame-probed, because only the thumbnail is displayed there and the video is checked when opened.
- GraphQL parsing now also covers user operations (profiles, follower lists) when profile protection is on, and still runs only while some X protection needs it.
- **“Not sensitive” marks** for classifier false positives, designed so they cannot become a shortcut: off by default (0 to 5 a day); only for images the classifier hid with a borderline score (explicit signal below 0.4 and suggestive below 0.85, never X labels, manual hides, videos, or GIFs); the background re-scores the image itself before accepting a mark; a mark takes effect 24 hours later in trusted time, so a clock change cannot bring it forward, and an alarm releases the image in open X tabs without a reload; a mark covers one image; removing it is always allowed and never refunds the day's count. The daily number shares the reveal allowance's lock rule (only down during an X lock or the allowance lock). Settings list every mark with its status.
- **False-positive notes** in the X protection and Adult websites section introductions, an About card (“Not perfect”), the X-label explanation in Why hidden?, the README, and the store listing.
- **Collapsed replies** no longer show the real @handle when name replacement is on; they use the alias.
- **Hide all of a post’s media when one is hidden** (opt-in): a classifier verdict on one image or video of a post also covers the rest of that post’s media, with the reason “Same post”. Before, only X labels and confirmed video verdicts covered the whole post; image verdicts stayed on their own cell. With the option on, safe media waits (still covered) until every item of its post has a verdict, so nothing flashes before a sibling’s verdict hides it. A quoted card is its own post. If the triggering item is released (for example by a “Not sensitive” mark), the others are checked again on their own. It stays editable during an X lock.
- **Lock scope:** a lock now protects the protection itself, not how hidden content is handled. An X lock keeps the level and sensitivity (only up), manual hides, and the reveal and mark limits (only down). The painting cover, text replacement, like blocking, hiding a post’s other media, and all of profile protection stay editable, because the media stays hidden either way. The adult-site lock keeps blocking on; SafeSearch stays editable. This replaces the earlier rule that locked text replacement, like blocking, and profile tightening.
- **Release preparation:** MIT license; full license texts of the bundled dependencies in `licenses/`, shipped in the package; a privacy policy (`PRIVACY.md`, linked from the About section); store listing copy and reviewer notes (`docs/AMO_LISTING.md`); `npm run package:source` builds the source archive for review from the committed tree; the README is rewritten for users, with build instructions for reviewers; the release checklist covers a listed AMO submission. The `custos` slug was free on AMO on 5 October.

## Video false-positive investigation

The supplied console file contains five distinct protected-video traces and three safe traces. The protected traces all report `reason: visual`. They do not include the active preset; Lenient is inferred from the supplied settings screenshot and is consistent with the decision thresholds. Unrelated X console errors are not evidence that the extension censored a video.

| Post ID | Captured full-frame scores, in sampling order | Previous decision |
| --- | --- | --- |
| 2102013906692530650 | .111, .756 | Single strong frame; check stopped after two samples |
| 2101878224376762506 | .456, .326 | Corroborated marginal result |
| 2102037342286495975 | .156, .004, .039, .417 | .156 counted as supporting evidence for .417 |
| 2102167969014968675 | .077, .099, .498 | Mean .225 exceeded Lenient's old .210 mean threshold |
| 2102168314189410343 | .119, .248, .516 | Weak second-frame corroboration |

The Lenient rule now requires two different full frames at or above 0.60. It does not classify center crops. Suspicion still triggers a second pass, up to six frames in total. Complete checks without this agreement release the video; an incomplete check cannot clear a flagged thumbnail. Logs now include the preset and diagnostic version so future reports do not require inference from a screenshot.

Regression tests replay these score patterns through the real coordinator. Unobserved continuation frames are explicitly synthetic clean frames, so passing tests does **not** establish that all five original videos now pass live, or that the new threshold meets a mature-content recall target. A synthetic repeated-strong-signal case verifies that Lenient still protects. This is a deliberate false-positive/sensitivity tradeoff, not a replacement model or an account/site allowlist.

## Validation and limits

- 0.5.0: 195 automated tests pass (`npm test`, 5 October). New coverage: post-wide hiding (held siblings, quote isolation, release after a mark, lock rule), “Not sensitive” marks end to end (eligibility, re-scoring, 24-hour delay under a clock jump, daily cap without refunds, lock rule, release and re-cover in the page, two-step request), collapsed-reply aliases, blur default and in-place sacred-art switching, the scaled-blur fallback, sacred art under locks, partial X saves never switching tiers off, account extraction without names/bios, profile scopes (including fail-closed everyone scope and own-picture exemption), stable aliases, marker opt-in, reply collapse and its metered reveal, profile lock tightening, account parsing only while needed, SafeSearch rewrites and lock, and link-preview cells.
- `npm run build`, `npm run lint:extension` (0 errors, warnings, or notices), and `npm run package` pass; the unsigned development package is `artifacts/custos-0.5.0.zip` (ignored by Git).
- The settings page, popup, block page, and X overlays (blur, sacred art, “Why hidden?”, aliases, blurred avatars, collapsed replies) were rendered in headless Chrome with the real HTML/CSS/JS, an isolated fake browser API, and a fake X page. This does not replace a live Zen smoke test or a check against live X responses: the location of X’s following, avatar, and banner fields must be verified live, and X’s real DOM for names, user cells, and hover cards may differ from the fixtures.
- 0.4.1 notes still apply: private corpus qualification, live rechecks of the five video posts, and signed-XPI release testing remain open. The evaluator covers default Balanced image scoring only; video policies and other presets need separate qualification; see `RELEASE_CHECKLIST.md`.
- No domains or media are sent to a classification/list service. Media pixels, scores, and account flags stay transient; manual choices, locks, and reveal usage stay in local extension storage. Only the maintainer update command downloads the upstream list.
- The domain list cannot identify every adult page or newly created domain. SafeSearch covers four engines only. The settings lock does not prevent browser-level add-on disabling/removal or a user editing their own profile.
